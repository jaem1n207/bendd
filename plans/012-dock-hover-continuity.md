# Dock hover 연속성과 초기 표시 — 모션 브리프

상태: 2026-10-02 사용자 승인 후 구현. 아래 설계와 실행 기록을 함께 읽는다.

대상은 실제 탐색 Dock과 홈 Craft Dock 데모다. 비교 기준은 현재 PR #149의 `caaf5f4`, 기존 `main`의 `1db9b73`이다. 클릭 단발 반동과 공유 툴팁의 방향 전환은 이전에 확정한 동작을 이어간다.

## 확인한 원인

- 실제 Dock은 기본 크기 40px로 렌더링한 뒤 `useEffect`에서 저장값을 rehydrate한다. 저장 크기가 다르면 첫 표시 이후 크기가 바뀐다.
- 기존 구현은 아이콘의 실제 width와 함께 컨테이너의 감지 범위도 커졌다. 현재 구현은 transform으로 확대하고 감지 영역은 기본 높이에 머무르며, `pointerleave`에서 확대를 해제한다.
- 크기 조절 손잡이와 슬라이더의 pointerdown, 설정 패널 진입에서 강제 focus를 호출한다. 포인터 조작과 키보드 조작을 구분하지 않아 focus-visible 테두리가 나타나는 경로가 있다.
- 사용 스택은 Motion 12, CSS, rAF 기반 임계감쇠 스프링이다. 공통 동작 감소 hook은 초기 상태를 보수적으로 처리하며 키보드 조작은 장식 이동을 생략한다.

## Motion brief — Dock hover 유지 영역

**Verdict:** animate

**Trigger:** fine pointer가 Dock 본체에 진입하면 확대를 시작한다. 시작 전에는 Dock 위 빈 영역에 진입하는 것만으로 확대하지 않는다. 시작 후에는 가장 크게 확대되는 아이콘의 툴팁 시작 지점, 즉 Dock 쪽 아래 경계 직전까지 같은 상호작용을 계속한다. 툴팁 요소 자체는 유지 영역에서 제외한다.

**Frequency:** 이전 브리프에서 확정한 방문당 몇 번에서 수십 번. 별도 재생을 기다리게 하지 않고 포인터를 연속해서 따라가는 반응을 유지한다.

**Purpose:** 확대된 아이콘 위로 이동하거나 좌우로 탐색할 때 대상과 툴팁이 갑자기 축소·소실되지 않도록 공간적 연속성을 보장한다.

**Enter:** 본체 진입 시 현재 크기에서 가로 포인터 위치에 대응하는 확대 크기와 이웃 아이콘 간격으로 이어진다. 아이콘은 scale과 translateX, 배경은 scaleX, 툴팁은 위치와 opacity로 반응한다. 같은 가로 위치라면 유지 영역의 어느 높이에서도 확대 크기는 같다. 높이에 따른 감쇠는 적용하지 않는다.

**Exit:** 포인터가 본체와 유지 영역 전체를 벗어나면 현재 위치와 속도에서 기본 크기·간격으로 복귀한다. 재진입하면 진행 중인 복귀에서 새 목표로 이어간다. 별도의 지연 시간이나 재생 대기열은 두지 않는다.

**Origin:** 아이콘의 가로 중심과 바닥을 기준으로 확대한다. Dock 전체의 가로 중심과 바닥은 유지한다. 좌우 이동 시 툴팁 상자는 이어지고 라벨은 기존 방향 전환을 유지한다.

**Easing:** 기존 임계감쇠 스프링, 주파수 26 · **Duration:** 포인터에 연속 반응하는 스프링이므로 고정 재생 길이 없음. 툴팁 라벨은 기존 cubic-bezier(0.22, 1, 0.36, 1), 160ms를 유지한다.

**Interrupt:** 포인터 반전·재진입은 현재 값과 속도에서 이어간다. Dock 크기나 확대 설정이 바뀌면 새 치수로 경계를 다시 계산한다. 설정 패널의 슬라이더 미리보기와 구분선 드래그 중에는 해당 조작을 우선한다. 창 blur, 숨김, unmount에서는 활성 상호작용을 정리한다.

**Reduced motion:** 장식적인 확대와 이동은 생략하고 대상 강조와 읽을 수 있는 툴팁을 유지한다. 명시적인 크기 조절·설정 미리보기·기본값 복원은 즉시 반영한다. 키보드 탐색은 정적 피드백을 유지한다.

**Stack:** 기존 rAF 스프링 driver와 CSS transform, Motion 툴팁. 새 애니메이션 패키지를 추가하지 않는다.

**Open risk:** 좌우 이동 중 최대 아이콘 높이와 Dock 너비가 바뀌면서 감지 경계가 흔들릴 수 있다. 현재 표시 크기와 새 목표 크기를 고려해 영역이 포인터 아래에서 갑자기 줄지 않도록 하고, 크기 32/40/64px 및 확대 1/1.6/2배에서 위쪽 왕복·좌우 왕복·경계 이탈·재진입을 확인한다. 좁은 화면에서는 실제 표시 가능한 확대 한도와 가로 스크롤 상태를 반영한다.

### 유지 영역의 조건

- 세로 범위는 Dock 본체부터 최대 확대 아이콘 위 툴팁의 아래쪽 경계 직전까지 연결한다. 아이콘과 툴팁 사이의 빈 공간에도 끊김이 없다. 커서가 툴팁 요소에 닿으면 유지 영역을 벗어난 것으로 처리한다.
- 가로 범위는 확대된 Dock의 시각적 범위를 따른다. 위쪽에서 구분선의 가로 위치를 통과해도 아이콘 반응은 계속된다. 툴팁의 너비 때문에 유지 영역을 추가로 넓히지 않는다.
- 구분선 본체에 직접 포인터를 올렸을 때의 안정적인 조절 타깃은 유지한다.
- 크기·확대 설정과 화면 제약으로 계산하며 임의의 고정 높이에 의존하지 않는다.
- 유지 영역 때문에 주변 콘텐츠의 클릭이나 스크롤을 가로채지 않는다. 다른 열린 패널·메뉴를 조작할 때 Dock이 반응하지 않도록 한다.
- 실제 Dock과 데모는 각각의 활성 상태와 경계를 사용한다. 데모 조작은 실제 Dock의 저장값에 영향을 주지 않는다.

## 함께 반영할 동작

### 저장한 크기로 첫 표시

유효한 저장값이 있으면 첫 화면부터 해당 크기로 표시한다. 기본 크기에서 저장 크기로 넘어가는 전환은 제거한다. 첫 그리기 전에 저장값을 검증하고 크기를 적용하며 hydration 이후에도 같은 값을 유지한다. 표시를 늦추는 페이드나 기본 크기의 임시 Dock으로 문제를 가리지 않는다. 저장값이 없거나 잘못됐거나 저장소를 읽을 수 없다면 기본값으로 시작한다. 기존 저장값의 버전 이관과 범위 검증을 유지하고 데모에는 적용하지 않는다.

### 기본값으로 복원

설정 패널에 `기본값으로 복원` 버튼을 추가한다. 한 번 누르면 크기 40px와 확대 1.6배를 함께 즉시 확정하고 저장한다. 패널은 열린 위치를 유지하며 숫자와 Dock이 같은 값을 표시한다. 데모에서는 데모의 두 값만 복원한다. 별도의 확인 창은 추가하지 않는다.

### 명확한 안내

패널 하단 문구를 `클릭하여 적용`으로 바꾼다. 기존 hover 미리보기·이탈 복원·클릭 또는 드래그 확정 동작은 유지한다.

### 입력 방식에 맞는 포커스 표시

마우스·터치로 구분선을 조작하거나 설정을 열거나 슬라이더를 누를 때 포커스 테두리를 표시하지 않는다. 키보드 Tab·방향키 등으로 조작하면 현재 조작 대상의 테두리가 즉시 나타난다. 포커스 자체와 키보드 조작 기능은 유지하며, 테두리를 전체적으로 제거하지 않는다. 마우스와 키보드를 번갈아 사용하는 경우도 확인한다.

## 구현 후 확인할 증거

- 각 버그의 실패 회귀 테스트를 먼저 실행하고 수정 후 통과시킨다.
- 저장값이 있는 재방문에서 hydration 전후 크기 일치와 최초 표시를 확인한다. 잘못된 저장값·저장소 차단·이전 저장 형식도 검증한다.
- 툴팁 아래 유지 영역에서 좌우 왕복할 때 툴팁이 닫히거나 확대가 초기화되지 않는지 확인한다. 본체 진입 전 위쪽 영역은 비활성이다. 툴팁 요소에 닿거나 유지 영역 전체를 벗어나면 정상 복귀해야 한다.
- 실제/데모 격리, 설정 미리보기와 유지 영역의 상호작용, 기본값 복원과 새로고침 유지, 포인터/키보드 포커스 전환을 확인한다.
- 기존 페이지 이동 위치 안정성과 동작 감소 동작을 보존한다. 검증하지 못한 브라우저·기기는 완료 보고에서 구분한다.

## 2026-10-02 실행 기록

- 서버가 출력하는 Dock 앞에서 검증한 저장 크기를 CSS 변수에 적용하고, hydration 시 같은 저장값을 복원한다. 저장소 접근 실패·잘못된 형식·범위 밖 값은 안전하게 처리하며 CSP는 변경하지 않는다.
- 본체에서 시작한 hover만 위쪽 영역으로 이어진다. 현재/목표 확대량과 세션 중 최대 높이로 유지 경계를 계산한다. 툴팁 아래 경계는 제외하고, 좌우 반전은 현재 스프링 속도에서 이어간다. 주변 클릭·스크롤을 막는 오버레이는 추가하지 않는다.
- 실제 Dock은 기본값 복원 시 크기 40px와 확대 1.6배를 한 번에 저장한다. 데모는 독립된 상태만 복원한다. 패널에 `클릭하여 적용` 안내를 표시한다.
- Dock과 포털 패널의 입력 방식을 추적한다. 마우스·터치는 윤곽선을 숨기고, 키보드로 전환하면 같은 DOM 포커스에 윤곽선을 표시한다. 키보드로 패널을 열 때 첫 슬라이더에 포커스를 옮긴다.
- 390×844 브라우저에서 최댓값의 숫자 말풍선이 1px 가로 overflow를 일으켜 패널 높이가 늘어나는 문제를 재현했다. 말풍선의 가로 이동을 트랙 안에 제한해 가로 스크롤과 높이 변화를 제거했다.

### 확인한 증거

- 초기 회귀 검사에서 9개 실패를 기록한 뒤 수정했다. 저장 크기의 hydration 전후 일치, 경계 유지·툴팁 진입 종료·상단 직접 진입 비활성, 좌우 반전, 32/40/64px와 1/1.6/2배 조합, 기본값 복원, 실제/데모 분리, 입력 방식 전환을 검증한다.
- 전체 단위 검사 52개 파일 / 505개가 통과했다. 좁은 화면 말풍선 위치 조정 후 Dock 관련 10개 파일 / 71개를 다시 확인했다. 타입·lint·포맷 검사와 최종 프로덕션 빌드도 통과했다. 기존 lint 경고 6건은 유지한다.
- 개발 브라우저에서 저장 크기 56px가 hydration 전 CSS와 아이콘 너비에 적용되고, hydration 후에도 유지되는 것을 확인했다. 초기 서버 ARIA 값은 hydration에서 저장값으로 갱신된다.
- 실제 Dock 본체에서 위쪽 유지 영역으로 이동했을 때 Craft 아이콘 너비 약 64px가 유지되고, 툴팁 영역에 진입하면 기본 40px로 복귀했다. 순수 pointermove 좌우 연속성은 driver 회귀로 확인했으며 브라우저의 상단 이동은 네이티브 드래그 경로로 확인했다.
- 마우스로 슬라이더에 포커스하면 브라우저의 `:focus-visible` 판정이 참이어도 테두리가 보이지 않는다. 방향키 입력과 키보드 설정 진입에서는 테두리가 보이고, Escape 시 구분선으로 포커스가 돌아온다.
- 최종 프로덕션 브라우저에서도 저장 크기 64px가 첫 관측 CSS와 아이콘 너비에 적용되었다. 64px·2배를 기본 40px·1.6배로 함께 복원했고 콘솔 오류는 없었다.
- 기본값 복원 뒤 패널 위치가 유지되고 두 설정이 즉시 복구된다. 390px 화면의 최대 크기에서도 페이지와 패널의 가로 overflow가 없다.

실제 터치 기기, Safari, 120Hz 성능과 연속 영상 프레임은 검증하지 않았다. Playwright CLI를 실행한 결과로 보고하지 않는다.
