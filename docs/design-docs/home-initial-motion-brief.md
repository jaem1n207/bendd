# Motion brief — 홈의 초기 등장

작성: 2026-09-30 · 상태: 첫 뷰포트와 이후 최초 진입의 900ms 순차 등장 통합 · 로컬 구현·검증 완료

**Verdict:** animate
**Trigger:** 홈 문서를 처음 열거나 새로고침한 뒤, 각 요소가 처음 뷰포트에 들어왔을 때.
**Frequency:** 문서 로드당 한 번. 사이트 내부 이동으로 홈에 돌아오거나 뒤로 가기로 복원할 때는 재생하지 않는다. 실제 일별 방문 횟수는 측정하지 않았으며, 반복 조작에 붙는 애니메이션으로 확장하지 않는다.
**Purpose:** 프로필 → 작업 → 실험 → 글의 정보 위계를 전달하고, 내용이 부드럽게 초점을 얻으며 나타나도록 한다.

**Enter:** 투명하고 흐린 상태 → 선명한 최종 상태. 텍스트는 `opacity: 0 → 1`, `blur: 10px → 0`, `translateY: 8px → 0`을 기본으로 한다. 대상 크기별 예외는 아래 표를 따른다.
**Exit:** 없음. 초기 등장의 역재생, 스크롤 아웃, 페이지 이탈 애니메이션을 추가하지 않는다.
**Origin:** 최종 배치보다 조금 아래에서 제자리로. 초기 등장에 스케일 변화와 바운스는 사용하지 않는다. 손글씨의 보조 회전은 선명화가 끝난 후 한 번만 적용한다.
**Easing:** `cubic-bezier(0.25, 0.1, 0.25, 1)` · **Duration:** 900ms. 부드럽게 시작해 중간에 선명해지고, 끝부분은 천천히 정착한다. 곡선은 홈에 제안하는 값이며 Linear의 정확한 원본 곡선이라고 주장하지 않는다.
**Interrupt:** 페이지 스크롤과 자동 위치 복원은 초기 시간표를 바꾸지 않는다. Tab 탐색, 실제 컨트롤 활성화·포커스, 테마 변경과 페이지 이탈은 해당 효과를 즉시 정리한다. 정적 본문의 터치 시작이나 페이지 스크롤 키는 조기 완료를 유발하지 않는다.
**Reduced motion:** 기존의 즉시 표시 정책 유지. 이동·흐림·순차 지연·손글씨 회전을 모두 제거한다.
**Stack:** 첫 화면 상태와 안전한 표시 복구는 CSS, 유한한 등장과 중단 처리는 Web Animations API, 화면 진입 감지는 IntersectionObserver. 새 모션 라이브러리는 추가하지 않는다.
**Open risk:** 작은 한글의 읽힘, blur의 합성 비용, 900ms 등장에 따른 LCP 영향. 아래 로컬 검증 기록에 측정값과 미검증 범위를 구분했다. 실제 모바일 기기의 성능을 보장하는 수치는 아니다.

## 확정한 결정

사용자의 최신 선택을 반영한다. 첫 버전의 140ms 스크롤 마무리는 폐기했다.

1. 스크롤해도 예정된 등장 순서와 재생 시간을 끝까지 유지한다. 이미 내려간 위치에서 로드되어도 해당 뷰포트 기준으로 정상 재생한다.
2. 개별 요소는 약 900ms에 걸쳐 선명해진다. 같은 섹션의 요소는 짧은 간격으로 겹쳐 시작한다.
3. 작은 텍스트와 목록에는 흐림 효과를 사용하고, 큰 Projects 미리보기는 투명도 중심으로 처리한다.
4. 손글씨는 같은 묶음의 마지막 본문 항목이 시작한 뒤 정확히 60ms 후에 시작한다. 본문 전체가 완료될 때까지 기다리지는 않는다.
5. 손글씨가 정상적으로 선명해진 후, 글씨 부분만 360ms 동안 한 번 회전한다. 반복·hover 재생은 추가하지 않는다.
6. 스크롤로 처음 보이는 Writing도 보이는 시점부터 900ms로 순차 등장한다. 페이지 로드부터 흐른 시간에 맞춰 중간 상태로 합류하지 않는다. 첫 화면 연출이 끝난 뒤의 최초 진입도 같은 정책이다.

프로필의 모든 요소가 **재생을 시작한 뒤** Projects를 시작한다. 프로필이 완전히 선명해질 때까지 Projects를 기다리게 하지 않는다.

## 레퍼런스에서 확인한 동작

[Linear — Conversations on Quality, Episode 05](https://linear.app/quality/05)를 새로고침하면서 실제 렌더링된 스타일과 화면을 연속 관측했다.

| 대상                | 관측한 동작                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| 제목·설명           | `blur(10px) → 0`, `opacity 0 → 1`, 아래 8px → 제자리. 두 요소는 같은 그룹으로 등장                      |
| 재생 버튼·보조 정보 | 주요 텍스트보다 뒤에 등장하는 별도 그룹                                                                 |
| 썸네일              | 아래 20px → 제자리, 흐림과 투명도 변화. 항목 사이에 대략 40~60ms의 시작 차이                            |
| 보조 텍스트         | 일부 요소에서 `mix-blend-mode: plus-lighter`가 시작과 종료 상태에 고정 적용                             |
| 선명해지는 시간     | 주요 텍스트에서 약 1초로 관측. 네트워크 대기와 첫 프레임까지의 시간은 애니메이션 지연으로 간주하지 않음 |

관측값은 프레임 샘플링 결과이며 원본 소스의 정확한 duration·delay·easing 선언값은 아니다. 현재 레퍼런스의 썸네일은 문서 순서로 등장했다. 홈에서는 사용자 요청에 따라 **선택된 항목이 있으면 그 항목, 없으면 첫 항목**을 우선한다.

## 초기 화면의 범위

- 첫 안정된 배치에서 실제 뷰포트와 겹치는 요소만 초기 순차 등장에 포함한다. 일부만 보이는 요소도 포함한다.
- 화면 밖 요소와 `display: none`인 손글씨 메모는 시간표에서 제외한다. 보이지 않는 앞 항목의 수만큼 지연을 누적하지 않는다.
- 초기 대상 집합을 정한 뒤에는 리사이즈나 늦은 데이터 때문에 전체 시간표를 다시 시작하지 않는다.
- 화면 밖 요소는 처음 뷰포트에 들어온 묶음마다 같은 시간표 함수를 사용한다. 본문과 손글씨 모두 900ms이며, Writing은 제목 → 첫 글 → 나머지 글 → 손글씨 순서다. 아직 화면 밖인 요소에는 효과를 만들지 않는다.
- 새 묶음은 최초 진입 시점을 기준으로 시작한다. 앞서 예약한 시작이 아직 미래라면 같은 stack은 36ms, 목록은 제목 뒤 36ms·본문 사이 60ms, 다른 섹션은 120ms 간격으로 연결한다. 이미 실행 중인 효과의 지연이나 진행률은 변경하지 않는다. 목록의 네 번째 시작 이후에는 추가 항목 수만큼 지연을 늘리지 않는다.
- 손글씨는 이미 예약했거나 이번에 진입한 같은 묶음의 마지막 본문 시작에서 60ms 뒤다. 아직 화면 밖인 본문을 기다리는 대기열은 만들지 않는다. 나중에 더 많은 본문이 들어와도 이미 시작한 메모를 숨기거나 다시 재생하지 않는다.
- 글꼴·데이터를 기다리는 빈 화면을 추가하지 않는다. 기존 600ms 표시 복구와 JavaScript 비활성화 대응을 유지한다. 이미 내용이 표시되었다면 뒤늦게 다시 숨겨서 초기 연출을 재생하지 않는다.
- 마스트헤드, 구분선, Dock의 기존 표시와 인터랙션은 이 시간표에 편입하지 않는다.

## 섹션별 시간표

`t = 0`은 초기 등장 재생의 시작이다. 각 시간은 **시작 시점**이며, 기본 지속시간은 모두 900ms다.

프로필과 Projects의 아래 요소가 모두 첫 화면에 포함된 경우의 기본 시간표:

| 섹션     | 요소                            |  시작 | 이전 시작과의 간격 |
| -------- | ------------------------------- | ----: | -----------------: |
| Profile  | person                          |   0ms |                  — |
| Profile  | intro                           |  36ms |               36ms |
| Profile  | bio 첫 문단                     |  72ms |               36ms |
| Profile  | bio 둘째 문단                   | 108ms |               36ms |
| Profile  | bio 셋째 문단                   | 144ms |               36ms |
| Profile  | 서명·GitHub·YouTube·Gmail 묶음  | 180ms |               36ms |
| Projects | 섹션 제목·아이콘·짧은 설명 묶음 | 300ms |          **120ms** |
| Projects | 프로젝트 이름·설명·태그 묶음    | 336ms |               36ms |
| Projects | 큰 미리보기 패널                | 372ms |               36ms |
| Projects | 프로젝트 링크 묶음              | 408ms |               36ms |
| Projects | 손글씨 메모                     | 468ms |               60ms |

2026-10-01 프로필 시안 반영으로 bio를 세 문단으로 나누었다. 시간표 알고리즘과 간격은 유지한다. 이 예시에서 person은 900ms, 프로필의 마지막 묶음은 1,080ms, Projects 링크는 1,308ms, 손글씨는 1,368ms에 선명해진다. 메모 손글씨의 보조 회전은 1,368–1,728ms에 실행된다. 프로필의 bendd 서명은 메모 회전과 별개의 일회성 선 그리기다. 요소 사이의 긴 대기 없이 선명화 과정이 겹친다.

섹션 간 기본 간격은 **앞 섹션에서 마지막으로 예약된 시작 시점 + 120ms**다. 해당 섹션에서 보이는 요소만 예약한다. 전체 섹션이 화면 밖이면 다음 보이는 섹션이 그 시간 슬롯을 이어받는다.

## Craft·Writing 목록

각 섹션의 시작을 `T`라고 할 때:

| 대상                                 |                                시작 |
| ------------------------------------ | ----------------------------------: |
| 섹션 제목·아이콘·안내/전체 보기      |                                   T |
| 선택된 항목 또는 첫 번째 보이는 항목 |                            T + 36ms |
| 나머지 첫 항목                       |                            T + 96ms |
| 나머지 두 번째 항목                  |                           T + 156ms |
| 추가 항목                            |           T + 216ms부터 동시에 시작 |
| 손글씨 메모                          | 같은 묶음의 마지막 본문 시작 + 60ms |

- 현재 Craft·Writing에는 선택 상태가 없으므로 첫 번째 보이는 항목이 선행한다. 선택 상태를 새로 만들지는 않는다.
- 선택된 항목이 화면 밖이면 이를 기다리지 않고 첫 번째 보이는 항목부터 시작한다.
- 등장 순서만 바꾸고 DOM 순서와 키보드 탐색 순서는 바꾸지 않는다.
- 카드·목록 항목은 각각 하나의 등장 단위다. 제목·요약·날짜·아이콘을 다시 잘게 쪼개어 중복으로 지연시키지 않는다.
- 부모 섹션과 자식 카드에 같은 blur·opacity 애니메이션을 중첩하지 않는다.
- 기여·연락 섹션이 초기 화면에 포함된다면 각 섹션을 한 묶음으로 취급하고 같은 섹션 간 간격을 적용한다.

**지연의 상한:** 마지막 시작이 600ms를 넘는 큰 뷰포트에서는 손글씨의 60ms 간격을 먼저 확보하고 나머지 간격을 같은 비율로 압축한다. 현재 세 개 손글씨 묶음의 예약분은 최대 180ms다. 본문 내부 간격과 섹션 간 간격의 비율, 손글씨의 정확한 60ms 간격을 유지하면서 마지막 시작을 600ms 이내로 제한한다. 개별 900ms 선명화는 유지하므로 내용은 재생 시작 후 최대 1,500ms에 선명해진다. 보조 회전까지의 최대 길이는 1,860ms이며 읽기나 컨트롤 조작을 기다리게 하지 않는다. 초기 뷰포트에 손글씨만 보이고 같은 묶음의 본문이 없으면 별도 60ms 대기를 만들지 않는다.

## 손글씨의 보조 회전

- 대상: `MarginNote` 안의 `p[data-note-accent]`. 넓은 등장 묶음, 화살표, 바깥 aside의 기존 −5°/+4° 기울기는 변경하지 않는다.
- 시작: 해당 손글씨의 정상 등장 완료 후. 이때 화면 밖이면 생략하며, 다시 화면에 들어와도 뒤늦게 재생하지 않는다.
- 지속: 360ms, 1회. 구간별 곡선은 `cubic-bezier(0.645, 0.045, 0.355, 1)`.
- 회전: 0%에서 0°, 35%에서 −1.2°, 70%에서 +0.4°, 100%에서 0°. 폭 640px 이하에서는 −0.6°/+0.2°로 줄인다.
- 중심: `transform-origin: 50% 70%`. 별도 blur·opacity·레이아웃 애니메이션을 중첩하지 않는다.
- 포커스·키보드 탐색·reduced motion·테마 변경·표시 복구로 즉시 표시된 경우에는 보조 회전을 시작하지 않는다. 진행 중 효과는 해당 입력과 페이지 이탈·unmount에서 해제한다.
- 정상 스크롤은 보조 회전도 재시작하거나 조기 완료시키지 않는다. 새 라이브러리, 프레임별 React 상태, 상시 `will-change`는 추가하지 않는다.

## 흐림과 합성

| 대상                                  | 데스크톱 시작 blur | 좁은 화면(640px 이하) 시작 blur | 시작 이동 | 종료                   |
| ------------------------------------- | -----------------: | ------------------------------: | --------: | ---------------------- |
| 프로필 텍스트·섹션 제목·프로젝트 제목 |               10px |                             6px |  아래 8px | 선명도 100%, 원래 위치 |
| Writing 항목                          |                8px |                             4px |  아래 6px | 선명도 100%, 원래 위치 |
| Craft 카드                            |                6px |                             3px |  아래 6px | 선명도 100%, 원래 위치 |
| 손글씨 메모                           |                4px |                             2px | 이동 없음 | 선명도 100%            |
| 큰 Projects 미리보기                  |           **없음** |                        **없음** |  아래 4px | 투명도 100%, 원래 위치 |

화면 크기별 값은 저사양 기기를 판별하는 장치가 아니라 흐림 면적과 글자 크기를 고려한 디자인 값이다. 실제 성능 검증은 별도로 필요하다.

`mix-blend-mode`는 서서히 보간하는 애니메이션 속성이 아니다. 레퍼런스에서 관측한 `plus-lighter`는 어두운 영상 위 텍스트의 합성 설정이다. 현재 홈의 밝은 배경·어두운 본문에 그대로 적용하는 대신, 이번 단일 레이어 등장에서는 **`normal`을 유지**한다. 색상과 대비를 유지하면서 `blur`·`opacity`·이동으로 선명화 질감을 재현한다. 두 레이어를 겹쳐 교차 페이드하는 별도 효과는 이번 명세에 추가하지 않는다. [MDN: mix-blend-mode](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/mix-blend-mode)

페이지 스크롤과 Projects 시연 내부의 스크롤은 구분한다. 내부 시연 조작은 해당 카드만 즉시 준비시키고, 페이지 전체를 다시 연출하지 않는다.

## 성능 기준

- 레이아웃을 움직이는 속성 대신 `opacity`·`transform`을 기본으로 하고, `filter: blur()`는 표에 지정한 작은 영역으로 제한한다. blur가 항상 합성 단계에서 저렴하게 실행된다고 가정하지 않는다. [web.dev: 고성능 애니메이션](https://web.dev/articles/animations-guide)
- 섹션·페이지 전체에 blur나 backdrop-filter를 적용하지 않는다. 배경 영상·이미지의 해상도를 늘리거나 큰 패널을 복제하지 않는다.
- 초기와 새 진입을 합쳐 blur가 예약·실행 중인 묶음은 최대 12개로 제한한다. 남은 예산에서 첫 항목·주요 텍스트에 우선 배분하고 나머지는 같은 시간표·900ms로 opacity·transform만 사용한다. 끝나거나 취소되면 예산을 반환하며, 느린 대기열을 추가하지 않는다.
- 200개 항목이 있어도 아직 진입하지 않은 항목에는 실행 중인 애니메이션이나 `will-change` 레이어를 만들지 않는다. 목록의 마지막 지연은 항목 수에 비례해 계속 늘어나지 않는다. 이미 시작한 초기 효과는 스크롤로 화면 밖에 나가더라도 유한한 시간표대로 끝난다.
- 초기 위치 읽기와 스타일 쓰기를 분리하고, 프레임마다 React 상태를 갱신하거나 레이아웃을 읽지 않는다. 손글씨 보조 회전 직전에는 해당 메모의 화면 포함 여부를 한 번 확인한다. 스크롤마다 스타일을 읽는 중단 경로는 제거한다.
- 완료 후 `filter: none`, `transform: none`으로 정리하고 임시 애니메이션 핸들과 레이어 힌트를 해제한다. 상시 `will-change`는 사용하지 않는다.
- 저성능 환경에서 부담이 확인되면 ① 큰 카드의 blur 제거 ② 작은 텍스트 blur 축소 ③ opacity 중심으로 축소한다. 모션을 유지하려고 사용자 입력을 늦추지 않는다.

## 구현 후 확인할 기준

1. 초기 화면에서 프로필 내부 간격이 섹션 간 간격보다 짧고, 프로필 마지막 묶음 시작 후 Projects가 시작한다.
2. 목록의 선행 항목이 먼저 보이며, 화면 밖 항목 때문에 시작 시간이 밀리지 않는다.
3. 정상 속도와 25% 속도에서 투명도·선명도가 역행하지 않는다. 이미 읽히던 글이 다시 흐려지는 프레임이 없어야 한다.
4. 휠·터치 시작·페이지 스크롤 키가 초기 시간표를 취소하거나 다시 만들지 않는다. Tab으로 접근하거나 클릭한 실제 컨트롤은 즉시 선명하며 실행 가능하다.
5. 화면 밖 본문은 처음 진입할 때 같은 900ms 선명화와 목록 순서로 한 번만 등장한다. 초기 연출 중 Writing으로 이동하는 경우와 연출 종료 후 첫 진입을 모두 확인한다. 손글씨의 60ms 후행과 한 번의 회전을 유지한다.
6. 밝은/어두운 테마, 좁은 화면, 높은 화면 배율, 느린 글꼴/스크립트, JavaScript 비활성화, reduced motion, 내부 경로 복귀를 확인한다.
7. 성능 기록에서 반복 레이아웃 계산, 큰 영역의 지속 재페인트, 모션 코드가 유발한 50ms 이상 긴 작업이 없어야 한다. 60Hz 환경에서 프레임 예산 약 16.7ms를 목표로 확인하되 미측정 상태를 통과로 기록하지 않는다.
8. 같은 조건의 기존 홈과 LCP·입력 반응·드롭 프레임을 비교한다. CPU 제한 테스트와 실제 중급 모바일 기기 측정을 구분해서 기록한다. 읽힘이나 성능이 나빠지면 흐림 범위를 먼저 축소한다.

## 경계

이 문서는 초기 뷰포트 등장에 대한 명세다. 기존 Dock, 폰트, 콘텐츠 배치, 포인터 인터랙션의 디자인을 변경하는 승인이 아니다. 승인 후 홈의 등장 코드와 직접 관련 테스트만 구현했다.

## 이전 구현 검증 — 2026-09-30 첫 버전

아래 기록은 스크롤 시 140ms로 마무리하던 첫 버전의 측정이다. 최신 스크롤 유지·손글씨 회전 구현의 검증으로 간주하지 않는다.

`HomeMotion`은 첫 페인트의 CSS 안전장치를 유지하고, 첫 화면의 시간표와 중단 가능한 WAAPI 효과를 관리한다. `home-reveal-plan.ts`는 섹션 간격·목록 우선순위·600ms 지연 상한·12개 blur 상한을 계산한다. Projects는 제목·미리보기·링크를 각각의 등장 단위로 나누었다.

- `pnpm test:unit run src/components/home`: **26개 통과**. 순서, 200개 목록의 지연 상한, 선택 항목 우선, 모바일 blur, 중단 시 현재 값 보존, StrictMode 정리, 키보드, reduced motion, 페이지 복원과 기존 시연 인터랙션을 확인했다.
- `pnpm build`: **통과**, 타입 검사·프로덕션 컴파일 포함. 홈 First Load JS는 107kB다. 기존 Tailwind/Hook 경고와 테스트의 Next Image `fetchPriority` 경고는 남아 있다.
- 실제 브라우저에서 정상·25% 속도 모두 opacity 역행이 관측되지 않았다. 완료한 요소는 `filter: none`, `transform: none`으로 정리된다. 초기 테마 클래스의 중복 적용이 모션을 중단하는 문제도 회귀 테스트로 고쳤다.
- 페이지 스크롤 시 현재 opacity·filter·transform에서 140ms 효과로 이어졌다. 다음 화면 샘플에서 완전히 선명한 상태가 관측된 시점은 스크롤 후 약 150ms였다. 이는 60Hz 프레임 샘플링의 해상도를 포함한다. 새로 진입한 화면 밖 미리보기는 지연 0ms·지속 280ms였다.
- 390×844 뷰포트에서 가로 넘침 없이 표시되고 텍스트 blur는 6px, 큰 미리보기 blur는 0px였다. 1280×2700 뷰포트에서는 20개 등장 단위 중 blur가 12개로 제한되고 마지막 시작은 600ms였다. Craft·Writing의 첫 항목이 나머지 항목보다 먼저 시작했다.
- 밝은/어두운 테마, Tab 즉시 표시, 스크립트 1.2초 지연 후 CSS 표시 복구를 확인했다. 늦은 초기화에서 다시 숨김이나 초기 애니메이션 재생은 없었다. 스크립트 실행이 금지된 iframe에서도 홈 내용이 표시됐다.
- 원본 로컬 서버에서 `/article` → Home 키보드 이동 시 20개 단위가 모두 즉시 `visible`이었다. BFCache 정리와 `back_forward` 문서 복원 분기는 단위 테스트로 검증했다.

### 성능 관측

같은 로컬 프로덕션 서버와 브라우저의 1280×720 화면에서 각 3초 동안 프레임 간격과 PerformanceObserver 기록을 수집했다. 임시 진단 페이지가 두 버전 모두 같은 방식으로 스타일을 샘플링했다. 다음 값은 각 조건의 단일 관측이며 벤치마크 평균이나 실제 사용자 지표가 아니다.

## 이전 구현 검증 — 2026-09-30 스크롤 유지·손글씨 후속 효과

아래는 새 뷰포트 요소를 280ms/200ms로 처리하던 버전의 기록이다. 이후 최초 진입도 900ms로 통합하는 변경의 검증 증거로 대신하지 않는다.

사용자의 후속 구현 승인에 따라 스크롤 중 140ms 마무리 경로를 제거했다. 정적인 본문의 포인터 시작과 페이지 스크롤 키도 시간표를 유지한다. 실제 컨트롤 활성화·포커스·접근성 설정에 따른 즉시 표시 경로는 보존했다.

손글씨는 마지막 본문 시작에서 60ms 뒤에 등장한다. 전체 초기 시간표를 600ms 안으로 압축할 때도 각 손글씨의 60ms 간격을 먼저 확보한다. 정상 등장 완료 후에는 글씨 `p`만 360ms 동안 한 번 회전하며, 화살표와 바깥 메모의 기울기는 그대로다.

- 회귀 테스트를 먼저 추가해 기존 구현에서 20개 실패를 확인한 뒤 수정했다. 최종 `pnpm test:unit run src/components/home`는 **47개 통과**했다: 시간표 8개, 모션 제어 33개, 기존 인터랙션 6개.
- 반복 스크롤·초기 양수 스크롤 위치·화면 밖 이동에도 기존 애니메이션이 유지되는지, 본문 입력과 실제 컨트롤 조작을 구분하는지 확인했다. 손글씨의 60ms 후행·좁은 화면 회전 각도·정상 완료 시 한 번만 실행·reduced motion/Tab/pagehide/unmount 정리도 포함했다.
- `pnpm build`의 프로덕션 컴파일·타입 검사·lint가 **통과**했다. 홈 First Load JS는 108kB로 이전 107kB에서 약 1kB 늘었다. 기존 Tailwind/Hook 경고와 테스트의 Next Image `fetchPriority` 경고는 별도 기존 항목으로 남아 있다.
- 로컬 프로덕션 브라우저의 정상·25% 속도 기록에서 opacity 역행은 관측되지 않았다. 실제 페이지를 초기 재생 직후 아래로 스크롤해도 900ms 효과의 인스턴스·지연·순서가 유지됐으며, 취소는 자연 종료 후 정리 단계에서만 발생했다. 새로 진입한 본문은 280ms·지연 0ms로 시작했다.
- 1280×2700 화면에서 전체 20개 초기 단위의 마지막 지연은 600ms였고, Projects·Craft·Writing의 메모는 각각 마지막 본문보다 정확히 60ms 뒤였다. 메모 3개에 보조 회전이 한 번씩 적용됐으며, 종료 후 글씨의 `transform`은 `none`으로 돌아왔다. 모든 프레임에서 화살표·aside의 기존 transform은 유지됐다.
- 390×844 화면에서는 가로 넘침 없이 표시되고 회전이 −0.6°/+0.2°로 줄었다. 이 결과는 데스크톱 브라우저의 좁은 뷰포트 검증이다.

## 최신 구현 검증 — 2026-09-30 Writing의 최초 진입 순차 등장

최상단의 재생 중 Writing으로 이동할 때 280ms로 빠르게 표시되던 별도 경로를 제거했다. 처음 보이는 요소에도 `createHomeRevealPlan`과 900ms 선명화를 재사용한다. 이미 예약된 효과는 유지하며 새 묶음만 뒤에 연결한다. 그룹별 본문 시작과 목록 항목 수를 보관해 교차 통지가 나뉘어도 간격과 목록 지연 상한을 유지한다.

- **회귀 테스트:** 변경 전 10개 실패를 확인한 뒤 수정했다. 최종 홈 테스트 **54개 통과**: 시간표 10개, 모션 제어 38개, 기존 인터랙션 6개. 재생 중/종료 후 Writing 첫 진입, observer 역순·분할 통지, 기존 인스턴스 유지, 총 blur 예산과 반환을 포함한다.
- **프로덕션 빌드:** 컴파일·타입 검사·lint 통과. 홈은 8.76kB, First Load JS는 반올림 기준 108kB다. 기존 Tailwind/Hook 및 테스트의 Next Image 경고는 남아 있다.
- **실제 재현:** 1280×720에서 최상단을 새로고침하고, 첫 효과 시작 후 약 91ms에 실제 페이지를 y=1512로 이동했다. Writing 제목과 글 3개·손글씨가 함께 보이는 위치였다. 앞서 시작한 효과에는 조기 취소가 없었다.
- **수정 전:** Writing 제목과 글들이 같은 시점에 delay 0·duration 280ms로 시작했다. **수정 후:** 제목을 T로 두면 첫 글 T+36ms, 두 번째 T+96ms, 세 번째 T+156ms, 손글씨 T+216ms이며 모두 duration 900ms다. 앞서 보이는 Craft와 기존 예약도 유지하므로 T 자체는 스크롤 시각보다 늦을 수 있다.
- **프레임 상태:** 정상·25% 속도 모두 opacity 역행이 없었다. 느린 재생의 한 중간 샘플에서 제목 opacity 0.204, 첫 글 0.126, 두 번째 0.035, 세 번째와 손글씨 0으로 순차 선명화를 확인했다. 마지막에는 모두 opacity 1·filter/transform none이었다. 손글씨 회전은 한 번만 재생됐다.
- **좁은 화면의 늦은 진입:** 390×844에서 초기 효과가 모두 종료된 뒤 약 23초에 Writing으로 이동해도 같은 900ms·36/60ms 순서였다. 제목 blur 6px, 글 4px, 메모 2px를 확인했고 가로 넘침이 없었다. 이는 데스크톱의 좁은 뷰포트 검증이다.
- **예산:** 재생 도중 스크롤한 기록에서 blur가 예약·실행 중인 단위는 최대 12개였다. 남은 예산이 없는 일부 글과 메모는 동일 시간표의 opacity·transform만 사용했다. 늦은 진입에서는 앞선 효과의 예산이 반환되어 Writing 전체에 지정된 blur를 적용했다.

### 이번 변경의 성능 관측과 한계

같은 임시 진단 코드로 DOM 스타일을 샘플링한 단일 실행이다. 정상 속도에서 변경 전/후 rAF 간격 중앙값은 모두 16.7ms, p95는 18.4/18.2ms였다. 변경 후에는 **66ms 간격 1회**가 초기 프로필 재생 중, 실제 스크롤 전에 관측됐다. 해당 실행의 Writing 재생 구간과 좁은 화면의 늦은 진입에서는 25ms 초과 간격이 없었다. 50ms 이상 긴 작업은 기록되지 않았다.

스크롤 입력 때문에 이번 LCP 후보 기록은 불완전하므로 전후 LCP 개선을 주장하지 않는다. 실제 모바일·CPU 제한·Safari/Firefox·네이티브 스크롤바 드래그·OS 설정 변경·전용 Paint 프로파일은 미확인이다. reduced motion·포커스·키보드·페이지 복원은 기존 회귀 테스트를 유지했다.

## 프로필 본문 자동 시연과 소셜 프리뷰 — 2026-10-01

사용자가 승인한 본문 두 효과를 기존 등장 흐름 뒤에 연결했다. `HomeMotion`은 정상적인 900ms 등장 완료에서만 `home:reveal-complete`를 보낸다. 접근성에 따른 즉시 표시, 내부 경로 복귀, 늦은 초기화의 표시 복구는 완료 신호를 보내지 않는다.

- 현재 화면에 보이는 프로필 등장 묶음이 완료되면 120ms 후 `클릭 한 번의 피드백`을 시연한다. 기존 아래쪽 기준 채움과 곡선을 사용하며 160ms 채움 + 300ms 유지 + 160ms 복귀, 총 620ms다.
- 120ms 후 `움직임의 타이밍`을 기존 720ms 선·점 효과로 시연한다. 색상·문구·배치·직접 조작의 효과는 유지한다.
- 각 문구는 문서 로드당 한 번만 자동 재생한다. 문구 전체가 화면에 들어오기 전에는 횟수를 소진하지 않고, 화면 밖의 앞 문구 때문에 보이는 다음 문구가 기다리지 않는다. 재생 직전에도 가시성을 다시 확인한다.
- 직접 문구를 hover하거나 컨트롤을 클릭·포커스하면 남은 자동 시연을 종료하고 직접 조작을 우선한다. Tab, reduced motion, 실제 테마 변경, 페이지 숨김·이탈, unmount에서도 타이머와 진행 중 자동 효과를 정리한다. 페이지 스크롤은 기존 등장 시간표를 취소하지 않는다.
- 자동 시연은 시각 효과만 실행한다. 클릭 이벤트를 흉내 내거나 `aria-live`에 클릭 완료를 알리지 않는다.
- 서명, 정적인 마지막 강조, 소셜 프리뷰에는 추가 자동 재생을 넣지 않는다.

소셜 프리뷰의 순간 스크롤바는 전체 높이를 채우는 콘텐츠의 `translateY(3px)` 때문에 발생했다. 수정 전 브라우저 기록에서 GitHub는 `clientHeight=252`, `scrollHeight=254`, YouTube는 각각 `210`, `213`으로 나타났다. 바깥 카드의 기존 위치·크기 변환은 유지하고 내부 콘텐츠는 190ms 투명도 전환만 사용한다. `overflow-y: auto`는 유지해 실제 높이 제한 상황에서 콘텐츠를 계속 스크롤할 수 있다.
